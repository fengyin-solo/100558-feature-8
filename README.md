# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

## 物料放行管控规则

放行不再是“谁都能按”：右上角可切换当前操作人（实名 + 角色 + 仓库归属），所有动作都按身份鉴权并写入操作日志，偏差可直接追责到人。

- **按仓库归属放行**：物料批号按前缀归属仓库（`YL/MATE` 原辅料仓、`BC` 包材仓、`CP` 成品仓），
  并在 `src/data/access.ts` 里按批号登记分工放行人。只有归属仓库的分工放行人能点动「确认放行/拒绝放行」，
  跨仓、仓管员、质量部一律拒绝，提示里写明批号归属与应操作人。
- **放行后只读**：已放行单据仅允许质量部再冻结；重复「确认放行」只计一次，不重复回写台账。
- **冻结/解冻归口质量部**：仓库不能自行冻结；冻结后必须由归属仓库「申请解冻」（附理由/复测依据），
  质量部审批通过后单据回到「待放行」，由分工放行人重新确认；审批驳回则维持冻结，可补正后重新申请。
- **状态机逐级推进**：`待放行 → 已放行/已拒绝`、`待放行/已放行 → 已冻结 → 待解冻审批 → 待放行/已冻结`，
  越级操作直接拒收；越权尝试也会留痕。
- **数量越界挡回**：放行数量必须为正数且不超过本单放行上限，并不超过关联批生产记录的投料量，否则挡回且状态不变。
- **单一数量来源 + 台账回写**：放行数量只以放行单为唯一数据源，批生产记录页与「放行台账」页共用同一份；
  放行/拒绝/冻结结论实时回写批生产记录的「放行台账回写」字段。
- **存量迁移**：浏览器里的旧结构数据在读取时由 `src/data/migrate.ts` 一次性回填仓库归属、分工放行人、
  放行上限与迁移日志，迁移幂等，重复打开不会重复回填。

业务规则与迁移分别有可回归的断言：

```bash
cd frontend
npm run verify     # 43 项放行规则断言 + 20 项存量迁移断言
```
